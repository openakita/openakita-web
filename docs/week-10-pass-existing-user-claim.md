# 第十周交付：Pass 存量账户认领

- 日期：2026-08-18
- 对应 PRD：Phase 2 P2.2
- 实现仓库：`D:\projects\go\stack-token-center`

## 本周目标

让存量 Pass 用户在不迁移资产、不按邮箱静默合并的前提下，将原账户绑定到
其控制的 OpenAkita Account，并为冲突、审计和回滚提供受控运维闭环。

## 已完成

- 管理员核验旧账户所有权后签发高熵一次性迁移码，数据库只保存摘要；
- 用户在 Pass 登录页输入迁移码后必须继续完成 Account OIDC；
- 认领成功只给原 Pass 用户写入 Account `sub`，用户 ID、余额、API Key、
  用量、充值和账单均保留原位；
- 新增跨 SSO 与认领流程共享的主体绑定表，阻止并发重复绑定；
- 覆盖 pending、authorizing、completed、conflict、locked、expired、
  cancelled、rolled_back 状态及追加式审计事件；
- 管理员可以查询记录、统计、事件，取消未完成流程或回滚误绑定；
- 回滚清除活动身份绑定、恢复认领前的角色/用户组/资料并撤销服务端浏览器
  会话；保留主体回滚占位，避免该主体自动创建第二个 Pass 用户；
- 鉴权改用当前用户缓存中的角色，认领或回滚后的权限变化立即生效，不信任
  登录时写入 Cookie 的旧角色快照；
- 提供用户通知模板、客服核验标准、冲突双人复核与上线门槛 Runbook。

## 明确不包含

- 根据邮箱、手机号、用户名或显示名自动合并；
- 两个已有 Pass 账户之间转移余额或 API Key；
- P2.3 普通本地登录切换策略调整；
- P2.4 Marketplace 余额支付。

## 主要验收

- 正常认领前后原用户 ID、余额和 API Key 所有权不变；
- 错误迁移码五次后锁定；
- 同一 Account `sub` 的重复或并发绑定安全失败；
- 同邮箱不同主体不会被合并；
- 回滚后 `oidc_id` 为空、浏览器会话撤销、业务资产仍在；
- SQLite、MySQL、PostgreSQL 均使用 GORM 可移植模型。
